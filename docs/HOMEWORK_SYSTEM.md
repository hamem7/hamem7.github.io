## 1) فكرة النظام باختصار

المعلم يجهّز واجبًا إلكترونيًا لطالب (أو لعدة طلاب) من نطاق حفظه، فينتج **رابطًا** يُرسله عبر واتساب. الطالب يفتح الرابط من هاتفه **بلا حساب**، يكتب اسمه ويحل الأسئلة. النظام يصحّح تلقائيًا ما أمكن، ويترك للمعلم ما يكتبه الطالب بنفسه. النتيجة المعتمدة تُحفظ في سجل الطالب وتغذّي «الواجب الذكي» القادم (يركّز على نقاط الضعف).

```
المعلم (جهازه)                    خادم Google Apps Script + Sheets                الطالب (هاتفه)
─────────────                     ────────────────────────────────                 ─────────────
إعداد الواجب ──createHomework──►  ورقة Homeworks
(محرك الأسئلة + الخطة الذكية)      
رابط ?hw=<id> ─────────── واتساب ──────────────────────────────────────────────►  يفتح الرابط
                                  ◄──getHomework (بلا الإجابات الصحيحة)─────────  
                                  ◄──submit (idempotent)────────────────────────  يرسل الإجابات
غرفة التصحيح ◄──listSubmissions──  ورقة Submissions
gradeSubmission ───────────────►  
history_<id> + أحداث التتبّع (محلي على جهاز المعلم)
```

## 2) المكونات

| `settings/homework-prep.*` | شاشة الإعداد: نوع (تلقائي/ذكي/يدوي)، طالب مستهدف، نطاق (كل النطاق / أحزاب / سور)، عدد الأسئلة (حد أدنى 15، أقصى 60)، مسودة أو نشر، وزر «توليد ونشر مباشرة» |

### ب) محرك الأسئلة — `engine/homeworkEngine.js`
يولّد أسئلة من نص القرآن المحلي (`database/quran-uthmani.json`). الصيغ الـ15 المسجَّلة في `engine/skillMap.js` (`HW_FORMATS`):

| المهارة | الصيغ |
|---|---|
| التسلسل | `mcq_next`, `mcq_prev` |
| الاستدعاء | `dropdown`, `dual_dropdown`, `written_blank`*, `write_3_ayahs`* |
| بنية الآية | `matrix_order` |
| الدقة/التمييز | `intruder_word` |
| السياق | `mcq_surah`, `ayah_ending`, `checkbox`, `matching`, `word_meaning` |
| الذاكرة البصرية | `visual_page` (يمين/يسار — ترقيم مصحف المدينة 604 صفحة) |
| التجويد | `tajweed_extract`* |

\* = يحتاج تصحيح المعلم يدويًا.
المشتتات (الخيارات الخاطئة) تُختار بالتشابه الرسمي للكلمة والطول والقافية لا عشوائيًا (`pickDistractorWords/Texts`). علامات الوقف تُستبعد من «الكلمات». معاني الكلمات من `database/data/wordMeanings.json` (كتاب «كلمات القرآن» لحسنين مخلوف، يُبنى بـ`tools/build_word_meanings.py`). أسئلة المتشابهات تُحقن عبر `engine/similarityInject.js`.

### ج) «الواجب الذكي» — التتبّع والتخطيط
- `engine/trackingEngine.js` (ملف خالص بلا DOM): كل أداء = **حدث** (موضع + مهارة + صيغة + دقة + زمن + جودة خطأ). منه فقط تُحسب: مستوى كل **مقطع** (10 آيات) — `unseen / needs_fix / shaky / solid / mastered` — ودقة كل مهارة (مع تلاشي نصف عمر 45 يومًا)، والتشخيص، وخطة الواجب القادم `planHomework`.
- أسقف الخطة (`THRESHOLDS`): علاجي ≤ 25%، المهارة الضعيفة ≤ 35%، اليدوي التصحيح ≤ 20% (حتى لا يُثقل المعلم).
- فواصل المراجعة بالأيام: `needs_fix 3 · shaky 5 · solid 14 · mastered 30`.
- المهارات الثماني: التسلسل، الاستدعاء، البنية، الدقة، السياق، البصرية، الطلاقة، التجويد (الطلاقة تُقاس في الحصة فقط).
- أنواع الخطأ التي يسجّلها المعلم يدويًا (`QUALITY`): لم يعرف · نسيان آية · أكثر من نقطة · كلمة تحتاج مراجعة · حركة تحتاج تصحيح (لكلٍّ وزن، وبعضها يدفع المقطع مباشرة إلى «يحتاج علاج»).
- «علاج الأخطاء»: بطاقة مرة يوميًا لكل طالب، والتثبيت بإجابتين صحيحتين في زيارتين مختلفتين.
- `core/trackingService.js` + `engine/trackingAdapters.js` + قاعدة `DarHamTracking` تربط المحرك بالتخزين.

### د) صفحة الطالب — `games/homework-play.*`
- تُفتح من `?hw=<id>` (مسار الإقلاع السريع في `core/app.js`).
- مسودة تلقائية محلية؛ الإرسال عبر `core/submitQueue.js` (معرّف `clientSubmissionId` ثابت، إعادة محاولة، يستأنف عند عودة الاتصال).
- لا يُعدّ الإرسال ناجحًا إلا إذا أعاد الخادم `persisted:true`.

### هـ) الخادم — `backend/Code.gs` (Google Apps Script، `VERSION 1.2.0`)
- تخزين فقط في Google Sheets: أوراق `Homeworks`, `Submissions`, `Teachers`، والسجل JSON مقسّم إلى chunks (45000 حرف × 8).
- إجراءات عامة: `ping`, `getHomework` (بلا الإجابات الصحيحة عبر `safeQuestion_`), `submit` (حد 500 تسليم/واجب و300000 حرف/طلب).
- إجراءات المعلم (بعد `googleSignIn`): `createHomework`, `listHomeworks`, `getHomeworkFull`, `setHomeworkStatus`, `listSubmissions`, `gradeSubmission` (مع `expectedVersion`), `voidSubmission`.
- حدود: 60 سؤالًا للواجب، 300 واجب للمعلم، 3000 إجمالًا.
- **(أُضيف 2026-10-13)** مزامنة سجل الطالب بين أجهزة المعلم: `syncManifest/syncPull/syncPush` على ورقة `SyncData` (دمج اتحادي في `engine/syncMerge.js`، تنسيق في `core/cloudSync.js`، زر «زامن الآن» في ملف المعلم). مراقبة الأخطاء: `logClientError` (عام ومحدود المعدل) و`listClientErrors` على ورقة `ClientLogs`، ومُبلِّغ الطالب `core/errorReporter.js`، وتنبيه في شاشة الواجبات.
- التنظيف اليومي (`dailyCleanup`، مفعَّل منذ 2026-10-06): معتمَد بالكامل → حذف بعد 20 يومًا؛ بلا تسليمات → 14 يومًا؛ غير مصحّح → لا يُحذف ويُنبَّه المعلم بعد 14 يومًا.

## 3) دورة حياة الواجب

1. **الإعداد:** المعلم يختار الطالب والنطاق والعدد ← `planHomework` يوزّع الأسئلة على المقاطع والمهارات الضعيفة ← المحرك يبني الأسئلة (أو بناء يدوي).
2. **النشر:** تسجيل دخول جوجل (مرة) ← `createHomework` ← نسخة محلية في `DarHamHomeworks` ← رابط `?hw=` للمشاركة بواتساب.
3. **الحل:** الطالب يدخل اسمه ويحل ويرسل.
4. **التصحيح:** إلكتروني لكل ما عدا النص الحر؛ **أي نص يكتبه الطالب = تصحيح يدوي** في «غرفة التصحيح» (قرار المعلم).
5. **الاعتماد:** `gradeSubmission` ← `recordApprovedResult` ← `history_<id>` + أحداث تتبّع تُغذّي الواجب التالي + شهادة.
6. **التنظيف** من الخادم بعد المدد أعلاه (نتائج الطالب تبقى محليًا فقط على جهاز المعلم).

## 4) القرارات الثابتة (لا تُغيَّر دون الرجوع للمعلم)
- HTML/CSS/JS خام + ES Modules، بلا فريمورك أو مكتبات جديدة.
- Local-first (IndexedDB)، الخادم Apps Script + Sheets بدل Firebase.
- الطالب بلا حساب؛ المعلم بجوجل فقط لنظام الواجبات، والتسجيل مفتوح لأي بريد موثّق، ومفتاح المعلم القديم أُلغي نهائيًا.
- نص القرآن/الأسماء يُحقن دائمًا عبر `esc()`؛ كل نص جديد في `core/i18n.js` بلغتين.
- لا تُعدَّل: أعمدة الشيت الثابتة، أسماء `action` وأكواد الأخطاء، أسماء قواعد `DarHam…`، مفاتيح `history_<id>`، `?hw=`.
- أي إجراء مؤثر (تفعيل مشغّل، حذف، نشر) لا يتم إلا بطلب صريح من المعلم.
- مع كل تعديل جوهري: رفع `APP_VERSION` + `CHANGELOG` و`CACHE_NAME`.
